# デスクトップGUI（Rust）

sasacodeのGUIは、sasacode本体を子プロセスとして動かすRust製のネイティブアプリとして作る。ElectronとTauri（WebViewを使う方式全般）は使わない。本体をRustへ書き換える大改修の先駆けとして、本体とGUIが共有する型を先に小さなクレートにしておく。最初の版の画面は[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（MIT）を参考にした（コードは流用していない）。今の画面は、先にHTMLのモックで決めた構成を、sasacodeが実際に出す情報に合わせて作り直したもの。

段階ごとの完了条件と状態は [milestones.md](milestones.md#guig0g4進行中) にある。

## 構成

| 部品 | 場所 | 役割 |
| --- | --- | --- |
| `sasacode-gui` | `crates/sasacode-gui` | 窓。入力ごとに `sasacode -p <入力> --output jsonl --control stdio`（続きなら `-r <id>`）を作業フォルダで起動し、stdoutのイベントを画面に出し、承認・追加の指示・中断をstdinに書く |
| `sasacode-protocol` | `crates/sasacode-protocol` | イベント、制御メッセージ、セッションログの型と、セッションの一覧。将来のRust版コアも同じ型を使う想定 |
| sasacode本体 | `packages/` | これまでどおり。エージェントのループ、ツール、権限確認、セッションの保存はすべてこちらに残るので、TUIとGUIで振る舞いがずれない |

中継のサーバーは置かない。Rust版のコアができたら、GUIは子プロセスをやめてコアのクレートを直接使う形に移れる。そのときも画面側は `sasacode-protocol` の型だけを見ているので、書き換えは接続部分（`runner.rs`）に収まる。

## プロトコル

GUIが使うのは、すでにあるヘッドレスの出力と制御だけ（[README](../README.md#ヘッドレスの制御)）。

| 画面 | 使うもの |
| --- | --- |
| 応答のストリーミング | `message_start` / `message_update` / `message_end` |
| ツールのカード | `tool_start` / `tool_update` / `tool_end` |
| 承認 | `approval_request` → stdinの `approval`（allow / always / deny、拒否の理由） |
| 実行中の追加の指示・中断 | stdinの `message` / `abort` |
| トークン数・料金 | `message_end` の `usage` と `usage` イベント |
| 会話の続き | `session` 行のIDを覚え、次の入力を `-r <id>` で起動 |
| 会話の一覧と読み込み | `$SASACODE_HOME/sessions/<フォルダ名>-<ハッシュ>/*.jsonl` を直接読む |
| コンテキストの使用量 | `session`行の`contextWindow`（モデルのコンテキスト長。このブランチのCLIから出る。古いCLIでは出ないので表示しない）と、直近の`message_end`の入力の大きさ |
| 脇の質問（`/btw`） | 開いている会話を`-r <id> --no-session`で読み、ログに書かずに答えさせる。承認が来たら断る |
| 分岐（直して送り直す、やり直す） | 会話のログの、そのメッセージの前までを新しいidのログに写し、それを`-r`で続ける |

画面を作るうえで効いてくる、プロトコルの性質：

- 承認は1件ずつ、順に届く。1つの応答に呼び出しが複数あっても、まとめては聞かれず、それぞれ実行の直前に聞かれる。だから承認カードは1枚で足りる。bashやeditのように並行して走れないツールは、その呼び出しが終わってから次が聞かれる。readのように並行できるツールは、許可されるとすぐ走り出すので、走っている最中に次が聞かれることがある（`packages/agent/src/tool-exec.ts`）。
- 拒否された呼び出し、規則やプラグインに止められた呼び出し、中断で走らなかった呼び出しには`tool_start` / `tool_end`が出ない。あるのは結果のメッセージだけで、本文の出だし（`The user denied this tool call.`など）で見分ける。
- セッションログにはツール結果の`details`が残らない。読み込んだ会話では、差分は呼び出しの引数から作り（行番号と前後の行はない）、終了コード、所要時間、承認の記録は出せない。
- 実行中に送ったメッセージは、次のターンで新しいユーザーメッセージとしてモデルに渡る。中断のあとに渡るときは、先頭に`[The user interrupted the previous response.]`というテキストの部品が付く（ユーザーの言葉ではないので、画面には出さない）。
- ハーネスがユーザーの代わりに送る注意（`[Reminder from sasacode, not from the user] `で始まる）と、サブエージェントの終了報告も、ユーザーのメッセージとして届く。吹き出しにはせず、注記として出す。

TS側が正。`crates/sasacode-protocol/tests/fixtures` に実際の実行の出力とそのセッションログを置き、`cargo test` で読めるかを確かめる。テストはTSのソース（`events.ts`、`control.ts`、`session.ts`）も読み、Rust側の知らないイベントの種類が増えたら落ちる。出力やログの形を変えたら `bun crates/sasacode-protocol/tests/fixtures/generate.ts` でフィクスチャを作り直す。今のフィクスチャは、`session`行に`contextWindow`を足す前のCLIの出力のまま。GUIが古いCLIの行も読めることの確かめを兼ねる（新しい行は`tests/protocol.rs`で確かめる）。

## 使い方

```bash
cargo run -p sasacode-gui -- <フォルダ>                     # PATHの sasacode を使う
SASACODE_BIN=/path/to/sasacode cargo run -p sasacode-gui    # 実行ファイルを指定（--sasacode でも同じ）
cargo install --locked --path crates/sasacode-gui           # sasacode-gui をPATHに入れる
```

`sasacode-gui`がPATHにあれば、sasacodeからも開ける。

- `sasacode gui [フォルダ]`：そのフォルダ（省略すると今のフォルダ）で窓を開く。
- TUIの`/gui`（同梱プラグイン`gui`）：今のフォルダで窓を開き、進行中の会話を読み込んだ状態にする（`sasacode-gui --session <id>`を使う。idは`sasacode -r`と同じ読み方で、そのフォルダの会話のid、idの先頭、ログのパスのどれか）。まだ何も送っていない会話にはログがないので、新しい会話で開く。
- 窓はsasacodeとは別のプロセスとして残り、sasacodeを終えても閉じない。
- 窓が動かすsasacodeは、単一バイナリのsasacodeから開いたときはそのバイナリ（`--sasacode`で渡す）。ソースから動かしているときと、`SASACODE_BIN`があるときは渡さず、窓が自分で探す（`SASACODE_BIN`、なければPATHの`sasacode`）。
- `sasacode-gui`の場所は`~/.sasacode/config.json`の`plugins.settings.gui.command`でも指定できる。プロジェクトの設定に書いた場所は、プロジェクトを信頼するまで使わない（`sasacode gui`は信頼の確認をしないので、常に使わない）。
- 起動のあと0.6秒待ち、そのあいだにエラーで終わったときはその旨を表示する（古い`sasacode-gui`が`--session`を知らない場合など）。確実ではない：初めて動かすプログラムは起動そのものに0.6秒より長くかかることがあり、そのときは見逃す。それより後の失敗も、sasacodeの側からは見えない。
- `/gui`で開いたあとは、TUIと窓のどちらか一方で続ける。TUIは窓が足した発言を読み込まない。窓も、一覧から会話を選び直すまで、TUIがその後に足した発言を表示しない。両方から続けると、ログには両方の発言が書かれた順に並び、次に再開したときにどちらの画面にもなかった会話になる。

窓は3つに分かれる。左がそのフォルダの会話の一覧、中央が会話と入力欄、右がインスペクタ。左右を両方出すと会話の幅が554より狭くなる窓では、左右のどちらかだけを出す（開いたときの幅なら、幅1180未満の窓）。

- 左右のパネルは、会話との境目をドラッグすると幅が変わる。一覧は180〜480、インスペクタは280〜760の範囲で、会話の幅を、左右を両方出しているときは554、片方のときは440より狭くしない。境目をダブルクリックすると、開いたときの幅（244 / 380）に戻る。
- 境目を最小の幅からさらに60寄せるとパネルが畳まれ、同じドラッグのまま戻すとまた開く。畳んだパネルは、上の端のボタンか`⌘B` / `⌘I`で、ドラッグを始める前の幅で開く。
- ドラッグ中は、窓の外に出たポインタも追う。窓の外で離しても、ドラッグはそこで終わる。窓の左右の外まで寄せると、パネルは畳まれるか、会話の幅を残せるだけの幅になる。
- パネルの幅と窓の大きさは`$SASACODE_HOME/gui.json`（既定は`~/.sasacode/gui.json`）に書き、次に窓を開くときに使う。書くのは、境目を離したとき、ダブルクリックで幅を戻したとき、窓の大きさを変えて0.5秒たったとき。変わっていなければ書かない。畳んだかどうかと窓の位置は覚えず、毎回両方のパネルを開いて始まる。
- 窓は760×520より小さくできない。`gui.json`の値は読むときに範囲に収める。窓は最小の大きさ以上、パネルはドラッグで取れる範囲にする。数でない値や読めないファイルは、初めて開いたときの値（1280×800、244 / 380）として扱う。覚えていた窓が今の画面より大きいときは、開いたあとで画面に収める。

- 入力欄は下にある。Enterで送信、Shift+Enterで改行（設定の画面で、Enterで改行、`⌘Enter`で送信にもできる。そのときは、下の表の`⌘Enter`の動きが`⌘⇧Enter`に移る）。実行中に送ると、次のターンでモデルに届く（届くまでは、その旨を添えて会話の末尾に出る）。
- 入力欄の下の段で、モデル（`provider/model`、空なら既定）、権限モード、推論の深さを次の実行に渡す。選んだものは下端のバーにも出る。
- 承認が要る呼び出しは、入力欄の上のカードに全文が出る（コマンド、編集の差分、それ以外は引数のJSON）。答え方は3つ：許可、この実行中は同じものを許可、拒否。入力欄に何か書いて送ると、拒否して、書いた内容を理由としてモデルに伝える。
- 終わったやりとりは、返答だけを残して手順（思考、ツール呼び出し、承認の記録）を畳む。「手順を表示」で開く。返答がないまま止まったやりとり（中断、エラー）は開いたままにする。
- インスペクタのタブは6つ：変更（writeとeditの差分）、計画（todoの最新の状態）、コマンド（bashの出力と終了コード）、使用量（入力・出力・キャッシュのトークン数、リクエスト数、直近の入力の大きさ、料金）、git（下を参照）、ファイル（ツリーと検索、色付きの表示と編集）。
- 左の一覧はそのフォルダの会話（TUIで作ったものも含む）。選ぶと読み込み、次の入力はその会話の続きになる。検索欄でEnterを押すと、見つかったうち最も新しい会話を開いて入力欄に戻る。
- 窓の文字は直接は選択できないので、コピーはボタンで行う（返事の一部は、読み取り専用の欄で開いて選び、引用として入力欄に入れられる）。返答（Markdownのまま）、コードブロック、コマンドとその出力（表示している末尾だけでなく全部）、エラーに「コピー」がある。押すと少しのあいだ「コピーしました」に変わる。下端のバーの会話idは、押すとidの全体をコピーする（`sasacode -r`に渡せる）。
- 会話は最新の位置にあるあいだ、届いた分だけ自動で下へ進む。上へ戻して読んでいるあいだは、届いても読んでいる位置を動かさず、「最新へ」のボタンを出す。最新まで戻るか、ボタンを押すか、送信するか、会話を開き直すと、また自動で進む。
- 一覧の題、上の題、下端のバーのフォルダのように途中で切った文字は、ポインタを載せると全文が出る。
- 画面の言語は `SASACODE_LANG`、なければ `LANG` で決まる（`ja` / それ以外は英語）。明暗は、設定の画面で決めなければOSの設定に従う。
- Linuxでは実行時に `libxkbcommon-x11` が要る（多くのデスクトップ環境には入っている）。

### ほかのエージェントのGUIに合わせて足したもの

Codex、Claude Code、T3 CodeのGUIと比べて足したもの。比べた表と、足さなかったものの理由は[gui-parity.md](gui-parity.md)にある。

- 会話は同時にいくつでも走らせられる。一覧で別の会話を開いても、走っている会話は裏で続く。一覧の印は、承認待ち（黄）、実行中（緑）、未読（裏で終わった、点）。入力欄に書きかけた文は会話ごとに残る。
- 一覧の行にポインタを載せると、ピン留め、名前の変更、アーカイブのボタンが出る。名前、ピン、アーカイブは`gui.json`に書き、ログは書き換えない。付けた名前は一覧、見出し、通知、`/export`の見出しに使う。アーカイブした会話は一覧の下の「アーカイブ」から見て戻せる。`⌘K`の検索は題だけでなくメッセージの本文も探す。
- 入力欄で`@`に続けて打つと、そのフォルダのファイルとフォルダの候補が出る（gitのリポジトリならgitが追うファイル、そうでなければフォルダの中を2万件まで）。`/`で始めると、この窓のコマンドの候補が出る（`/new`、`/btw`、`/find`、`/export`、`/steps`、`/model`、`/rename`、`/pin`、`/archive`、`/delete`、`/group`、`/branch`、`/window`、`/folder`、`/open`、`/terminal`、`/tui`、`/editor`、`/worktree`、`/worktrees`、`/run`、`/outline`、`/split`、`/usage`、`/automations`、`/jobs`、`/gist`、`/settings`、`/keys`）。CLIとプラグインのスラッシュコマンド、スキルも並び、`--slash`で走らせる。候補は`↑` / `↓`で選び、TabかEnterで入れ、Escで閉じる。
- 空の入力欄の1行目で`↑`を押すと、前に送ったメッセージが戻る。TUIと同じ`$SASACODE_HOME/history.jsonl`を読み書きする。
- 窓にファイルを落とすと`@パス`で入る。文字のないクリップボードで`⌘V`を押すと、画像をPNGで`$SASACODE_HOME/pasted/`に書いて`@パス`で入れる（macOSはosascript、Windowsはpowershell、Linuxは`wl-paste`か`xclip`。TUIと同じ読み方）。1週間より古いものは次に貼るときに消す。画像はCLIの画像プラグインが添える。
- メッセージにポインタを載せると、「直して送り直す」と（最後のメッセージなら）「やり直す」が出る。どちらも、そのメッセージの前までのログを写した新しい会話を作り、元の会話は残す。中断して今すぐ送ったメッセージは、実行が閉じるのを待つ間、「取り消して入力欄に戻す」で入力欄に戻せる。
- `/btw 質問`で、会話を読んだうえでの脇の質問に答えさせる。答えは窓の上に出て、会話のログには残らない。
- `⌘F`で、会話を合うやり取りだけに絞る（Escで閉じる）。メッセージの下には送った時刻（「3分前」など）が出る。`/export`で会話をMarkdownにしてクリップボードへ写す（下端のバーに「コピーしました」が出る）。
- 画像を添えたメッセージは、ログの中では画像プラグインの`[Image 1: 絶対パス]`になっている。ログから読み込んだ会話では`@パス`に戻して表示し、「やり直す」や「直して送り直す」でもその形で送るので、画像プラグインが画像をもう一度読む（ファイルが消えていれば付かない）。
- インスペクタのgitタブ（`⌘5`）：ブランチ、まだプッシュしていないコミットの数、コミットしていないファイルとその差分。ファイルごとにステージ、外す、取り消す（2度押す）、エディタで開く、フォルダで表示。コミット（何もステージしていなければすべて）、プッシュ（上流がなければ`-u origin`）、PRの作成（`gh pr create --fill`）。差分の行をクリックすると`@パス:行`が入力欄に入る。下の帯にはブランチ名が出て、押すとコピーする。
- 下の帯の「コンテキストN%」は、直近の入力がモデルのコンテキスト長のどれだけかを示す（75%で黄、90%で赤）。
- 窓が後ろにあるあいだに実行が終わる、承認を待つ、止まると、OSの通知で知らせる（macOSはosascript、Linuxは`notify-send`。Windowsでは出さない）。実行中はコンピュータをスリープさせない（macOSは`caffeinate -i`、Linuxは`systemd-inhibit`。画面は消えてよい。Windowsではしない）。
- コマンドパレット（`⌘⇧P`）は、コマンド、タブ、テーマ、拡大、最近使ったモデル（ログに残るもの）、会話のあるほかのフォルダを探して実行する。ほかのフォルダは新しい窓で開く。`/worktree`は、新しいブランチ（`sasacode/<日時>`）のgit worktreeを`$SASACODE_HOME/worktrees/`に作り、新しい窓で開く。
- 設定の画面（`⌘,`）：Enterキーの動き、実行中のメッセージ（割り込ませるか順番待ちか）、テーマ（システムに合わせる、ライト、ダーク）、アクセントの色、フォント、表示の大きさ（70%〜160%）、通知（終わったとき・承認を待つとき・音・前にあるときも）、スリープさせないか、道具の呼び出しを会話に出すか、失敗だけ出すか、考えたことを出すか、PRが閉じたら自動でアーカイブ、次の入力の提案、会話の幅、言語、しばらく使わない会話のアーカイブ、エディタ、sasacodeの実行ファイル、ワークツリーの準備コマンド、覚えた「常に許可」の一覧。どれも`gui.json`に書く（キーは`enterSends`、`theme`、`zoom`、`notify`、`awake`、`steps`など。会話の名前、ピン、アーカイブは`names`、`pinned`、`archived`）。

### 2回目に足したもの（`gui/parity-all`、2026-11-17）

比べた表は[gui-parity.md](gui-parity.md)の「2回目の洗い出し」。主なもの：

- 見た目：Solid Glass（[deeplethe/solid-glass](https://github.com/deeplethe/solid-glass)、MIT）に寄せた配色と部品。アクセントの色（緑・青・紫・橙・桃か`#RRGGBB`）と、文字とコードのフォント名を設定で選ぶ（フォントは次に開く窓から）。
- `/usage`：会話をまたいだ使用量。日ごとのグラフ、モデルごと、費用、会話ごと。全フォルダとこのフォルダを切り替える。
- `/compare`：1つのメッセージを複数のモデルに送り、分割表示で比べる。
- プランモード：権限モードの「plan」（`⌘⇧L`で通る）。`ask`で走らせ、読み取りだけを許し、書き込みと編集は窓が拒否し、コマンドは確認する。システムプロンプトに「計画を書いて終える」と足す。計画が書けたら入力欄の上の「この計画で進める」で、前に選んでいたモードで進める。CLIの設定ファイルのallowルールが許す呼び出しは、プランモードでも確認なしで通る（CLIはルールをモードより先に見るため。拒否するフラグもない）。
- `/automations`：自動実行。毎日・平日・N時間ごとに、決めたメッセージを新しい会話で送る。モードは`plan`・`ask`・`edits`・`agent`から選び、`auto`は選べない。ウィンドウが開いている間だけ動き、閉じている間に過ぎた分は、開いたときに1回だけ走る。OSのスケジューラには登録しない。同じフォルダの別のウィンドウで止めたり消したりしたものは、もう一方も走らせず、書き戻さない。
- `/gist`：会話をMarkdownにして、`gh`でsecret gistを作る。毎回、送り先とURLを知る人は読めることを確かめてから作る。
- `/jobs`：background-sessionsプラグインの`bg_start`で始まったジョブの一覧。状態、終了コード、出力の終わり。走っているものは2回押しで止める（プラグインの`bg_stop`と同じく、プロセスがまだそのジョブのものかを確かめてからプロセスグループにSIGTERM。macOSとLinuxだけ）。ファイルから読むので、プラグインを読み込まない。
- `/worktrees`：このリポジトリのワークツリーの一覧と、変更のないものの削除（ブランチは残す）。新しいワークツリーでは設定の準備コマンドを走らせ、`.worktreeinclude`に書いたファイルやフォルダ（`.env`など）をコピーする。`/worktree <ブランチ>`でベースを選ぶ。
- PRのチェックを45秒ごとに見て、終わったら知らせる。下書きのPR、レビュー可能にする、自動マージ、マージの方式。
- 一覧：下に「ほかのフォルダ」（sasacodeを使ったほかのフォルダ。押すとそのウィンドウで開く）。絞り込みに「完了」。下書きのある行に鉛筆の印。
- ファイルタブ：何も打っていないときはフォルダのツリー。gitタブ：変更をフォルダごとにまとめて畳める。
- 「このアプリについて」：「更新を確かめる」で`sasacode update --check`を走らせ、その1行を出す（何も入れない）。
- リンク：`sasacode://open?folder=…&session=…`を引数に渡すと、そのフォルダと会話で開く。`⌘⇧C`でコピーする。OSへのURLスキームの登録はしていない。
- 「拡張」画面：AGENTS.mdがないとき、エージェントに書いてもらう依頼を入力欄に入れる。
- エディタで開くとき、行の分かるファイルはVS Code系・Zed・Sublime Text・JetBrainsならその行で開く。
