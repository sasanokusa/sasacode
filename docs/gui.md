# デスクトップGUI（Rust）

sasacodeのGUIは、sasacode本体を子プロセスとして動かすRust製のネイティブアプリとして作る。ElectronとTauri（WebViewを使う方式全般）は使わない。本体をRustへ書き換える大改修の先駆けとして、本体とGUIが共有する型を先に小さなクレートにしておく。

段階ごとの完了条件と状態は [milestones.md](milestones.md#guig0g4進行中) にある。

## 画面の考え方

ほかのハーネスのGUIを小さく写したものにはしない。チャットの吹き出しを上から下へ積む形をやめ、頼んだ人が読む順に並べる。

- 窓は、地の上に1枚の紙を置いた形にする。地の左に、このフォルダの会話の一覧がある。紙の上にあるのは1つの会話だけ。
- 会話は1本の茎として描く。依頼ごとに節があり、節の下に、した作業と答えが続く。節の色は状態を表す（終わったものは緑、進行中はゆっくり明滅する緑、承認待ちは黄、失敗は朱、答えのないまま終わったものは白抜き）。
- 開いているのは、いまの依頼だけ。前の依頼は「依頼」と「答えの最初の1文」の2行に畳む。それより前は「以前の依頼 3件」の1行にまとめる。どれも押せば開く。長い会話でも、紙の上は読む量のままになる。
- 答えが出たら、その前の作業（思考、ツールの呼び出し）は「作業 4件」の1行に畳み、内訳（実行 2、読み取り 1、編集 1）を横に出す。実行中は最新の5行だけを出し、いましていることと経過時間をその下に1行で出す。
- 承認は会話の中に流さず、入力欄のすぐ上に出す。コマンドはそのまま、編集と書き込みは消える行と入る行で見せ、確認する理由（権限の設定、ルール）を文で添える。拒否する理由もそこに書ける。答えるまで同じ場所にあるので、探さなくてよい。
- 実行が終わると、紙は上に戻る。答えは最初から読める。実行中に自分でスクロールしていたら、位置は動かさない。
- できることは、すべて「探す、操作する」（Ctrl+K、macOSは⌘K）から届く。会話を開く、モデル・権限・推論の強さを選ぶ、変更したファイルを開く、答えをコピーする。入力欄の中の3つの設定も、同じ一覧を開く。
- この会話が変更したファイルは、紙の右に並べて見られる（Ctrl+D）。ファイルごとに1回ずつ、入った行と消えた行の数と、変更の中身を出す。
- 最初の画面は、何を書けばよいか、次の依頼に効く設定、キーの一覧を見せる。使い方を別の場所へ読みに行かなくてよい。
- 窓が狭いときは、あるものを縮めずに、置き方を変える。幅が780より狭いと会話の一覧を出さず（会話は「探す、操作する」から開ける）、変更したファイルは会話の横ではなく紙の全体に出す。
- 文言は [yomiyasu](https://github.com/nanaism/yomiyasu) の決まりに従う。誰が何をするかを述語まで書き、飾りの記号やダッシュを使わない。

見た目の決まりは次のとおり。

- 色は、緑がかった地と紙、墨の4段階、笹の緑（主な操作と進行中）、黄（人を待っている）、朱（失敗と拒否）だけ。読む文字に使う色（墨の上の3段階、緑、黄、朱）は、どちらの配色でも背景との比が4.5:1以上ある。墨の4段階目は、まだ押せない操作と入力欄の例文にだけ使う。明るい配色と暗い配色を同じ名前で持つ。
- 影とグラデーションは使わない。重なりは面の色の差で表す。
- アイコンは [Lucide](https://lucide.dev) の必要な32個だけを小さなフォントにして埋め込む（`assets/icons.ttf`、作り方は `assets/icons.py`）。文字や絵文字をアイコンの代わりにしない。
- 文字の大きさは11、12、13、15、20の5つ。等幅はコード、パス、コマンドにだけ使う。

色は `style.rs`、アイコンは `icon.rs`、文言は `i18n.rs`、状態は `app.rs`、「探す、操作する」の中身は `palette.rs`、会話のデータと畳み方は `transcript.rs` にある。見た目は `view.rs`（窓と一覧）、`view/conversation.rs`（茎）、`view/dock.rs`（承認と入力欄）、`view/find.rs`、`view/changes.rs` に分けてある。

## 構成

| 部品 | 場所 | 役割 |
| --- | --- | --- |
| `sasacode-gui` | `crates/sasacode-gui` | 窓。入力ごとに `sasacode -p <入力> --output jsonl --control stdio`（続きなら `-r <id>`）を作業フォルダで起動し、stdoutのイベントを画面に出し、承認・追加の指示・中断をstdinに書く |
| `sasacode-protocol` | `crates/sasacode-protocol` | イベント、制御メッセージ、セッションログの型と、セッションの一覧。将来のRust版コアも同じ型を使う想定 |
| sasacode本体 | `packages/` | これまでどおり。エージェントのループ、ツール、権限確認、セッションの保存はすべてこちらに残るので、TUIとGUIで振る舞いがずれない |

中継のサーバーは置かない。Rust版のコアができたら、GUIは子プロセスをやめてコアのクレートを直接使う形に移れる。そのときも画面側は `sasacode-protocol` の型だけを見ているので、書き換えは接続部分（`runner.rs`）に収まる。

## プロトコル

GUIが使うのは、すでにあるヘッドレスの出力と制御だけ（[README](../README.md#ヘッドレスの制御)）。

| 画面 | 使うもの |
| --- | --- |
| 応答のストリーミング | `message_start` / `message_update` / `message_end` |
| ツールのカード | `tool_start` / `tool_update` / `tool_end` |
| 承認 | `approval_request` → stdinの `approval`（allow / always / deny、拒否の理由） |
| 実行中の追加の指示・中断 | stdinの `message` / `abort` |
| トークン数・料金 | `message_end` の `usage` と `usage` イベント |
| 会話の続き | `session` 行のIDを覚え、次の入力を `-r <id>` で起動 |
| 会話の一覧と読み込み | `$SASACODE_HOME/sessions/<フォルダ名>-<ハッシュ>/*.jsonl` を直接読む |

TS側が正。`crates/sasacode-protocol/tests/fixtures` に実際の実行の出力とそのセッションログを置き、`cargo test` で読めるかを確かめる。テストはTSのソース（`events.ts`、`control.ts`、`session.ts`）も読み、Rust側の知らないイベントの種類が増えたら落ちる。出力やログの形を変えたら `bun crates/sasacode-protocol/tests/fixtures/generate.ts` でフィクスチャを作り直す。

## 使い方

```bash
cargo run -p sasacode-gui -- <フォルダ>                     # PATHの sasacode を使う
SASACODE_BIN=/path/to/sasacode cargo run -p sasacode-gui    # 実行ファイルを指定（--sasacode でも同じ）
```

キーは次のとおり。macOSでは Ctrl の代わりに ⌘ を使う。

| キー | すること |
| --- | --- |
| Enter | 送信する。実行中に送ると、次のターンでモデルに届く |
| Shift+Enter | 改行する |
| Ctrl+Enter | 承認待ちなら許可する。そうでなければ送信する |
| Ctrl+. | 実行を中断する |
| Ctrl+K | 「探す、操作する」を開く。↑と↓で選び、Enterで決め、Escで戻る |
| Ctrl+N | 新しい会話を始める |
| Ctrl+D | 変更したファイルを出す、しまう |
| Ctrl+B | 会話の一覧を出す、しまう |
| ↑（入力欄が空のとき） | 直前の依頼を入力欄に戻す |

- 左の一覧はそのフォルダの会話（TUIで作ったものも含む）。選ぶと読み込み、次の入力はその会話の続きになる。「探す、操作する」に言葉を入れても探せる。
- モデル（`provider/model`）は、この窓で使ったものと、このフォルダの会話が使ったものから選べる。一覧にない名前は、モデルの一覧で名前を入れると「（名前）を使う」が出る。
- 選んだモデルと推論の強さ、使ったモデル名、会話の一覧をしまったかどうかは `$SASACODE_HOME/gui.json` に覚える。権限は `edits` と `ask` だけ覚え、`agent` と `auto` は窓を開くたびに選び直す。
- ファイルを窓に落とすと、そのパスが入力欄に入る。
- 窓がほかの窓の後ろにあるときに、承認が要るか実行が終わると、OSの方法で知らせる（Dockやタスクバーの印）。
- 画面の言語は `SASACODE_LANG`、なければ `LANG` で決まる（`ja` / それ以外は英語）。明暗はOSの設定に従う（`SASACODE_THEME=light|dark` で固定できる）。
- macOSでは、タイトルバーを窓の中に溶かし、窓の上の端をつかんで動かす。OSのタイトルバーに戻すには `SASACODE_TITLEBAR=system` を付けて起動する。
- Linuxでは実行時に `libxkbcommon-x11` が要る（多くのデスクトップ環境には入っている）。

## 確かめたこと、確かめていないこと

Linuxの仮想ディスプレイ（Xvfb）で、決まった応答を返す偽の `sasacode` を相手に、送信、承認（許可と、理由を付けた拒否）、実行中の指示、中断のあとの表示、会話の読み込み、「探す、操作する」、変更したファイル、明暗、日本語と英語、狭い窓（幅600）を画面の写真で確かめた。描画はGPU（lavapipe）とCPUの両方で見た。

次は確かめていない。

- macOSとWindowsでの表示と操作。とくにmacOSの、タイトルバーを溶かした窓（信号の位置との重なり、窓をつかんで動かすこと）、ヒラギノとMenloでの文字の並び、⌘のキー。
- 実際のIME（変換中の文字と候補の位置）。
- ファイルを落とす操作と、後ろにある窓からの知らせ。仮想ディスプレイでは起こせない。
- 実際のモデルを相手にした長い実行。

## 未決事項

- 本体とGUIを別々のバイナリで配るか、`sasacode gui install` で後から入れる形（`web-search install` と同じ）にするか。
- 入力ごとの再起動で体感が許せるか。遅ければ、`--control stdio` に「`agent_end` の後も終了せず次の入力を待つ」モードを足す。
- TUIとGUIが同じセッションを同時に開いたときの扱い。
- モデルの一覧をプロバイダーから取る方法。いまは使ったことのあるモデルだけを出す。CLIに一覧を出力するコマンドができたら、それを読む。
- シェルの関数や `.zshrc` だけで設定したAPIキーは、Finderなどから開いたGUIの子プロセスに渡らない。`$SASACODE_HOME/.env` に書けば渡る。
